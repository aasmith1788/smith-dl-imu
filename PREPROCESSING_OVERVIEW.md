# Preprocessing Pipeline with April 2022 Fixes

The IMU workflow converts raw sensor recordings into normalized arrays for neural network training. In early 2022 the team discovered that some sensors were mounted with axes misaligned to the lab coordinate frame. They updated the first two notebooks—`0_Data_sorter.ipynb` and `1_Data_Checker.ipynb`—to rotate each signal before any further processing. When all notebooks are run in order, this fix propagates automatically and the final dataset is correctly oriented.

**1. Sorting and early checks.** `0_Data_sorter.ipynb` gathers each subject's accelerometer and gyroscope logs along with motion capture files. It renames them into a standard format so later scripts can access them consistently. After April 2022 it also applies the orientation rotation as soon as the files are loaded. `1_Data_Checker.ipynb` then confirms that no packets were dropped, timestamps increase monotonically, and the rotated values remain within expected ranges.

**2. Manual review.** `2_Data_PDFViewNCheck.py` plots each trial and exports a PDF for inspection. The researcher marks recordings to keep or discard. This step helps exclude corrupted sessions that automated checks might miss.

**3. Synchronization and filtering.** `3_0_Data_filtertoSave.ipynb` aligns IMU signals with the force plates, applies a low-pass filter and trims the recording to a single gait cycle. The resulting CSVs normally go in `preperation/NORM/`. During the initial orientation fix the outputs were sent to `preperation/NORM_CORRECTION` instead so the team could compare old and new versions side by side.

**4. Time normalization and exclusion.** `3_1_Data_timenormalized.ipynb` resamples each trial to exactly 101 time points, ensuring consistent length across the dataset. Optionally, `3_2_Data_Exclusion.ipynb` lets the user drop any trial that still looks questionable after filtering.

**5. Dataset assembly.** Finally, `4_DataSet_CAN_MYWAY.ipynb` loads the normalized files, splits them into five folds and saves `.npz` archives along with min–max scalers. In the April 28 commit these archives were placed under `preperation/NORM_CORRECTION` with the name `IWALQQ_1st_correction`. A day later the notebook reverted to saving under `NORM` with `IWALQQ_2nd_correction`, but the axis rotation remained in the earlier notebooks.

**Why the correction matters.** Before April 2022, training models on the misaligned signals produced biased predictions because forward movement sometimes registered along the wrong axis. By rotating the data at the start of the pipeline the issue was removed entirely. The temporary `NORM_CORRECTION` directory allowed the team to regenerate every intermediate file without overwriting prior results. Once they verified that the corrected data produced consistent joint angle predictions, they moved back to the standard `NORM` folder to keep paths simple.

To reproduce the cleaned dataset yourself, activate the conda environment specified in `preperation/buIMU.yml` and run each notebook in numerical order. The initial two notebooks apply the orientation fix, the next ones filter and time-normalize the signals, and the last builds the dataset. Whether you output to `NORM_CORRECTION` or `NORM`, the final arrays will be aligned to the lab frame. The April adjustments therefore safeguard against the earlier axis problem while leaving the overall workflow unchanged.

**Running the notebooks.** Clone the repository and either use the 28 April 2022 commit `f273d2b4` or the following commit `11079502`. Create the conda environment with `conda env create -f preperation/buIMU.yml` and activate it with `conda activate buIMU`. Launch Jupyter and open the notebooks in sequence. Each produces its outputs in the same directory structure used during the 2022 experiments, so you can directly compare the generated CSVs and final `.npz` files with the originals. The rotation fix in the first two notebooks ensures that the sensor axes remain consistent even if you use a newer version of the repository. Everything else—from filtering parameters to the shape of the dataset—matches the historical pipeline. Following these steps reproduces the corrected dataset exactly as it was used for the subsequent model training.
