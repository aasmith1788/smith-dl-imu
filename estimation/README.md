# Estimation

This directory contains all notebooks and utilities used after training to estimate knee kinematics and kinetics from IMU recordings. It is divided into two complementary workflows.

## Sensorwise

The **sensorwise** folder stores evaluation notebooks such as `makeEstimationwithPDF_wDgMini.ipynb`, `makeEstimationwithPDF_wDgMOSTyle.ipynb`, and `makeEstimationwithPDF_woDg.ipynb`. They load trained checkpoints and run predictions one trial at a time using the full 42‑channel input tensor (7 IMUs × two sensor types × 3 axes). The outputs for each trial are saved as Excel files so that additional scripts can compute errors and generate figures.

Despite the folder name, these notebooks do *not* mask any channels. Early cells fix `SEQ_LEN = 101` and `NUM_FEATURES = 42`, and every call to the model uses tensors of shape `(1,101,42)` along with the demographic vector. "Mini" simply loads a smaller network defined in `CBDtorch.dense_dg_mini` with a 10‑dimensional demographic embedding. "MOSTyle" changes the architecture but follows the same evaluation loop. The inner loop iterates over `dataIndex` to process each trial; it never loops over sensors.

If you want to study the impact of dropping a sensor, you must edit the code yourself—zero out or remove the appropriate columns before calling the model and optionally retrain to match the new normalization. The resulting Excel files can still be analyzed with the helper scripts.

Several utilities live beside the notebooks:

* `impulse_calculation.py` reads the per‑trial spreadsheets and writes summary impulse metrics to `Result_impulse/`.
* `peak_detection.py` examines the same data to locate gait peaks and saves the results in `Result_peak/`.
* `plot_CBD.py` produces per‑axis plots for manual inspection.

These scripts accept the prediction files generated by the notebooks and distill them into compact CSVs for further aggregation.

## Notsensor

The **notsensor** folder contains two different types of notebooks. The first set—including `maketable.ipynb` and `maketable_withDecay.ipynb`—merges the CSV outputs from `Result_peak` and `Result_impulse` into summary tables. This step finishes quickly on any machine, making it easy to regenerate averages after you create new spreadsheets.

The second set evaluates other architectures using all sensors at once. Examples are `makeEstimationWithPDF_PyramidAttnCNNOPT.ipynb`, `makeEstimationWithPDF_DenseAngleArch.ipynb`, and `makeEstimationWithPDF_Optuna_1dCNN.ipynb`. These notebooks load their own checkpoints, run inference across the full dataset, and save predictions under the `DenseModel/` directory. Their CSV layout mirrors the sensorwise results so that the aggregation scripts can combine everything seamlessly.

## Typical workflow

1. Train your models under `training/`.
2. Run a sensorwise notebook such as `makeEstimationwithPDF_wDgMini.ipynb`. This produces per‑trial Excel files inside `wDgMiniModel/` and enables `peak_detection.py` or `impulse_calculation.py` to compute additional metrics.
3. To test custom sensor configurations, modify the notebook to drop specific columns before inference, then rerun it to create a new set of spreadsheets.
4. Launch `notsensor/maketable.ipynb` to merge the spreadsheets into overall rRMSE and correlation tables. Repeat whenever you add new results.
5. For full‑sensor benchmarks or alternative architectures, execute one of the notsensor inference notebooks. Place its outputs in `DenseModel/` and rerun `maketable.ipynb` to see them alongside the sensorwise data.

## When to use each workflow

Choose **sensorwise** when you need fine‑grained trial results or wish to experiment with subsets of sensors. The notebooks are computationally heavy because they loop through every trial, but they provide the flexibility to analyze individual IMU contributions.

Choose **notsensor** when you only need to aggregate existing spreadsheets or compare a new full‑sensor architecture. Merging tables runs in seconds, while the full‑sensor inference notebooks give a baseline of how the model performs with all seven IMUs intact.

Together these subfolders allow you to mix and match experiments. Sensorwise scripts generate the detailed predictions and specialized metrics. Notsensor scripts either summarize them or run alternative networks that keep all sensors active. Because every tool saves data in the same CSV format, you can easily recompute tables as new models are trained or as you experiment with different sensor combinations.
